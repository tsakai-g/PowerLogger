# Security / セキュリティ

## Never commit private deployment data / 公開してはいけない情報

- The `SHARED_SECRET` generated by Apps Script `setup()` (the script sources contain only generation logic).
- The deployed `script.google.com/macros/s/.../exec` URL if you intend to keep it private.
- Signing keys (`*.jks`, `*.keystore`) and signing passwords.
- Real email addresses in `server/Code.gs` or in screenshots/logs.
- Device database files, CSV exports, and personal power-interruption records.
- OAuth/API tokens or personal `local.properties` files.

The code intentionally contains public placeholder recipient addresses. Replace them **only in your Apps Script editor**, not in a public GitHub commit. Keep the actual signing key on the owner's computer. `.gitignore` is a safeguard, not a substitute for reviewing diffs.

For an existing installation, do not run `setup()` again: use `updateAllowedRecipients()` to change the allowlist without changing the shared key.

The Apps Script web app is deployed with public endpoint access (`Anyone`) so an Android app can call it without a Google OAuth login. The endpoint validates an HMAC and a strict recipient allowlist. This is suitable for low-volume notifications, not for adversarial or safety-critical infrastructure.

The Android app keeps recipient, URL and shared key in app-private preferences; **this version does not encrypt the key with Android Keystore**. Do not expose app backup data or a rooted device. HTTPS is required.

If any shared secret is exposed in a Git commit or log, rotate it. Removing the file from the current branch is not enough because Git history may retain the secret.

アプリのソース、設定例、鍵生成コードは公開可能です。実際に生成された共有鍵、署名鍵、通知先アドレス、稼働URL、停電履歴は公開しないでください。鍵を誤公開した場合はGitの履歴から削除するだけでなく、鍵を更新してください。
